# 데이터 활용 명세

모든 숫자는 아래 원자료를 계산 도구(`app/engine.py`, `app/advisor.py`, `app/place.py`, `app/walk.py`)가 직접 세어 냅니다. 언어 모델은 숫자를 만들지 않습니다. 허브 파일·행정동 경계·지형은 `build/fetch_data.py --check` 가 sha256으로 대조하므로 같은 결과를 다시 만들 수 있습니다. OSM 도로·표선 보행 자료는 받은 시점의 자료라 받는 질의 원문을 남기지 않았고, 다시 받으면 결과가 달라질 수 있습니다(개발 PC 원본 sha256은 README에 적었습니다).

## 1. 제주데이터허브

답사 기준은 [서울시 상권분석서비스](https://golmok.seoul.go.kr/main.do)의 점포·인구 비교 방식을 참고합니다. 서울 수치나 평가 점수를 가져오지 않고, 아래 제주 자료로 계산합니다.

**검증 사례 — 반경을 바꾸면 경쟁점 비교가 달라지는가?** 상가 자료(2025-09-18)에서 애월 조사 지점(위도 33.462, 경도 126.311)과 조천 조사 지점(33.542, 126.669) 주변을 같은 직선반경으로 집계했습니다. 각 칸은 `카페 수 / 음식 업종 전체 점포 수`입니다.

| 조사 지점 | 300m | 500m | 1km |
|---|---:|---:|---:|
| 애월 | 18/58 | 19/64 | 28/132 |
| 조천 | 12/130 | 22/217 | 33/327 |

카페 수는 300m에서 애월이, 500m에서 조천이 많습니다. 반면 음식 업종 중 카페 비중은 세 반경 모두 애월이 높습니다. 두 지점의 비교이지 읍 전체의 순위나 매출 전망이 아닙니다. 유동인구와 사업체 변화는 읍면동 배경으로만 해석하며, 개별 점포의 매출·월세·실제 보행량은 이 자료로 확인할 수 없습니다.

| 자료 | 허브 번호·주소 | 기준 | 앱에서 쓰는 곳 | 가공 |
|---|---|---|---|---|
| [제주특별자치도 상가(상권) 정보](https://jejudatahub.net/api/file?id=5789&fileId=4692) | data/793 | 2025-09-18, 57,865곳 | 점포 위치(3D 점포), 동네별 업종 수·비중, 생활 이웃(마트·병원·약국·학원) 수, 후보 카드, 점포 카드 | 좌표를 앱 평면 좌표(원점 126.55E 33.38N, m)로 바꾸고 행정동에 배정. `web/data/stores.bin`, `web/data/stores/{동코드}.json`(상호·업종·주소) |

앱이 읽는 센터 자료(위 표의 파일과 API 응답)는 이 PC 안에서만 계산하며, 앱이 그 숫자를 외부 모델로 보내지는 않습니다. 다만 입력칸에 사람이 직접 적은 문장은 자유 대화를 켜 두면 아래 조건 안에서 그대로 모델로 갑니다. 길이·숫자 개수로 거르는 장치는 민감한 내용인지까지 판단하지 못합니다. **센터 전용 자료를 보며 입력하는 PC에서는 `자유대화끄고실행.bat`(바깥 호출 없음)으로 켜세요.**

자유 대화를 켜면 모델(Gemini, 시험 경로는 OpenAI)로 나가는 것은 사용자가 적은 문장(200자 이하, 두 자리 이상 숫자 2개 이하), 현재 조건(업종 이름·손님 방식·지역·동/읍면과 사용자가 말한 경쟁·이웃·성장 여부), 도구 결과 중 남은 후보 수·후보 동네 이름·빠진 이유·지도에 보여 준 동네 이름뿐입니다. 점포 수·인구 같은 숫자와 원자료는 보내지 않습니다. 이 조건을 넘는 글은 모델로 보내지 않고 이 PC 안에서 처리합니다. 이 PC의 `logs/model_requests.jsonl`에는 호출 시각·차례 수·글자 수·도구 이름만 남고 문장 원문은 남지 않습니다. 바깥 호출을 모두 끄려면 `자유대화끄고실행.bat`으로 켜세요(모델과 유동인구 API 모두 끔).

## 3. 계산 규칙 (요약)

- **같은 업종 비중**: 동네의 같은 소분류 점포 수 ÷ 그 동네 전체 점포 수. 카드의 "음식점 중 카페 비중"은 분모가 같은 동네 음식(대분류) 점포 수입니다.
- **생활 이웃**: 소분류가 슈퍼마켓·의원·병원(동물병원 제외)·약국·입시·교과학원인 점포 수. 43개 동네 중간값과 비교합니다.
- **촘촘함**: 동네 점포 수 ÷ 행정동 면적(㎢).
- **답별 기준**: 단골 → 생활 이웃·촘촘함, 찾아와 머무는 손님 → 숙박 업소·같은 업종이 모인 정도, 아직 모름 → 두 기준의 1순위를 나란히. 같은 업종 비중은 순위에 조금만 쓰고 주의점으로 따로 적습니다. 사용자가 말하지 않은 "경쟁 적은 곳" 조건은 넣지 않습니다.
- **점포 주변 질문**: 건물을 누르면 반경 35m 안 점포를 "주변 점포"로 보여 주며, 그 건물에 입점했다고 단정하지 않습니다.
- **가정 보행**: OSM 에 그려진 길 위 최단 경로, 걸음 분당 67m 가정. 가게 표시점이 길에서 15m 넘게 떨어져 있으면 "지나가는지 판단 못 함"으로 둡니다. 관측 유동이 아닙니다.

## 4. 쓰지 않는 것

- 임대료, 매출, 권리금: 자료가 없어 셈하지 않습니다.
- 골목·거리 단위 유동인구: 읍면동 단위 자료를 거리로 나누지 않습니다.
- 임대 매물: 지도 위 점과 후보는 매물이 아닙니다.
